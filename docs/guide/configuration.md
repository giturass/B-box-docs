# 编辑与应用配置

MITM、HTTP 改写和脚本保存在当前 sing-box JSON 的顶层 `experimental` 中。可以通过高级页面编辑，也可以使用原始 JSON 编辑器。

## 从页面进入

在配置列表长按目标配置，选择 **编辑**，进入高级配置：

| 页面 | 可编辑内容 |
| --- | --- |
| MITM | HTTPS 开关、域名与排除项、HTTP/2、服务器证书校验、TCP、QUIC 回退、证书入口 |
| HTTP 改写 | Header / URL / Body Rewrite、Map Remote、Map Local、资源 |
| 脚本 | 总开关、HTTP 脚本、Cron 任务和资源 |

端口、应用筛选以及其他细节可在对应 JSON 表单中编辑。**页面新建的示例规则或任务默认禁用**：修改内容后，还要把 `disabled` 设为 `false`，并开启所属扩展的 `enabled`。

## 三个扩展应当平级

```json
{
  "experimental": {
    "mitm": {
      "enabled": false,
      "hosts": []
    },
    "http_rewrite": {
      "enabled": false
    },
    "scripts": {
      "enabled": false
    }
  }
}
```

这只是**配置片段**。将需要的字段合并进已有配置，保留你的 `inbounds`、`outbounds`、`dns`、`route` 和其他 `experimental` 设置。

不要在同一个 JSON 对象里写两份 `experimental`，也不要把脚本嵌进 `http_rewrite`。同类规则应合并到同一个数组，顺序会影响实际行为。

JSON 不接受省略号、尾随逗号或未转义的换行。正则表达式中的反斜杠也要转义，例如域名中的 `\.` 在 JSON 字符串里写成 `\\.`。

## 什么时候生效

配置保存经过修订检查和完整核心校验。启用的扩展随 **本地服务成功启动或重载** 生效；保存到未选中的配置不会改变当前运行实例。

编辑当前正在运行的配置时，等待保存和服务应用流程完成；失败提示出现时先解决错误，不能把按下保存按钮视为已经生效。切换配置后同样要确认运行状态。

单纯校验、格式化、导入、预览或备份不会执行脚本，也不会下载外部资源。文件和 URL 资源在运行时加载，所以“保存成功”还不能证明外部资源可用。

## 停止操作分别影响什么

| 操作 | 结果 |
| --- | --- |
| 停止请求记录 | 停止保存记录；MITM、改写、脚本与 Cron 继续运行 |
| 关闭 `http_rewrite.enabled` 并成功应用 | 停止声明式改写；独立 MITM、脚本不随之关闭 |
| 关闭 `scripts.enabled` 并成功应用 | 停止 HTTP 脚本与 Cron |
| 关闭 MITM 并成功应用 | HTTPS 不再进入解密处理；符合范围的明文 HTTP 仍可改写 |
| 停止本地服务 | 结束全部配置处理、Cron 与在途资源下载 |

## 订阅、导出与备份

规则随配置分享、导出和备份保存。远程订阅更新会重新应用订阅内容，**不要把手工编辑当作长期覆盖层**；需要长期维护的本地规则，可以另存为本地配置，或在订阅源中维护合并结果。

以下内容仍留在本机，不会随配置迁移：

- MITM 根私钥、CA 身份和信任安装状态。
- 请求记录与记录设置。
- 脚本持久存储值、已下载的资源缓存。
- `script_path` / 文件资源引用指向的实际文件。

换设备后需要重新准备证书和资源。详见[文件与远程资源](../reference/resources.md)。
