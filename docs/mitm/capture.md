# 记录、详情与导出

**工具 → 请求** 负责保存与展示流量。解密与改写由配置负责；可以只记录不改写，也可以在不记录时继续改写。

## 开始记录

1. 先启动 B-box 本地服务，确认运行成功。
2. 在请求页设置应用、原始目的端口、每方向正文限额及域名提取。
3. 开始记录，再让目标客户端发出新请求。
4. 根据域名、URL 等搜索，打开请求详情。

抓取期间不能修改记录设置，需要先停止。尚未被接管的旧连接需要由目标应用重新建立；启用记录不能追溯补录此前正在传输的内容。

## 区分记录类型

| 类型 | 能看到什么 | 说明 |
| --- | --- | --- |
| HTTP / HTTPS | URL、方法、状态、头部、正文、时长等 | HTTPS 需要成功完成 MITM |
| 仅域名 | 可见的 TLS/QUIC 名称 | 只观察到名称，不表示已解密 |
| TLS/TCP | 双向解密字节前缀与 TLS 元数据 | 非 HTTP 流，不执行 HTTP 改写 |

HTTPS 和 TLS/TCP 可记录真实 SNI、两端 TLS 版本、客户端/上游 ALPN 及上游叶证书摘要。Mock 没有实际连接上游时，不会编造上游 TLS 信息。

## 正文与连接 ID

正文预览显示保存字节数、总字节数以及截断、未完成、Base64 等状态。完整 JSON 可切换原文与格式化；复制使用内核提供的原始预览，不代表尚未保存的完整正文。

有原始连接关联时，详情显示“连接 ID”。同一 HTTP/1.1 连接中的多条请求或 HTTP/2 流可能共享它；请求自身 ID 仍用于详情与导出。跨目标改写时，连接出站与路由信息描述的是原连接。

## 默认记录边界

| 项目 | 默认或上限 |
| --- | --- |
| 目标端口 | 80、443、8080、8443；最多 32 项 |
| 应用范围 | 空列表不限应用 |
| 保存条数 | 最多 300 条 |
| 磁盘记录额度 | 32 MiB |
| 每方向正文 | 默认 64 KiB，可设至 1 MiB |
| 预览与 HAR 解码 | 最多 64 KiB |

达到保存前缀上限只影响记录，不会因此截断实际转发流量。记录正文限额与 **改写正文限额**、**脚本正文限额** 分开设置。

## 导出

| 导出类型 | 使用条件 |
| --- | --- |
| HAR | HTTP 请求/响应；保留完整性标志与原始前缀，可能包含截断数据 |
| cURL | 完整、未截断、没有 trailers 的 HTTP 请求 |
| 域名 | 对当前搜索条件下保留记录中的域名去重 |

TLS/TCP 和仅域名记录不能作为 HTTP 导出。HAR 的 trailers 放在扩展字段 `_trailers`，耗时只有总时长；导出不能恢复未保存的完整正文。

## 停止与清空

停止记录会封存当前已保存内容，迟到数据不再更新这些记录。处理和转发继续运行；下次开启记录从新 HTTP 请求或新 TCP 流边界开始。

停止本地服务后仍可读取已保存记录。清空记录不会删除脚本持久数据、远程资源缓存或 CA；切换到远程会话会停止本地记录，并禁止读取本机记录与证书。

## 在哪里看错误

运行错误和脚本 `console` 输出进入现有 **服务日志**，遵守核心日志等级。没有独立的“抓包日志”页面。需要查看 `console.log` 时，确保配置日志等级允许 `info`，页面筛选也没有隐藏它。
