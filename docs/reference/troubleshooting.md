# 常见问题与排错

优先按“流量是否经过本地服务 → 配置是否生效 → 范围是否命中 → 证书/正文/脚本条件”排查。每次只改变一个条件，重新发出请求观察结果。

## 完全没有请求记录

- 本地服务是否已运行，请求页是否已开始记录。
- 请求是否经过该服务；使用演示配置时，curl 是否指定了 `127.0.0.1:2080` 代理。
- 原始目标端口是否在记录范围内，应用筛选是否把目标排除了。
- 是否仍在复用启用前未被接管的旧连接；关闭目标连接后重新请求。
- 是否切到了远程会话；本机记录和证书只对本地服务开放。

监听代理端口与原始目标端口不同：访问 HTTP 的演示请求通常是目标端口 80，不能按代理端口 2080 筛选。

## 只有域名，没有 HTTPS 正文

“仅域名”表示观察到 TLS/QUIC 名称，不表示已经解密。依次检查：

1. 当前已启动配置中的 `mitm.enabled` 是否为 true，`hosts` 是否非空。
2. 实际 SNI 是否命中第一条域名规则，是否先被排除。
3. 端口和应用条件是否满足，目标客户端是否信任当前 CA。
4. 流量是否是 HTTP/3、真实 ECH 或其他不支持的场景。

QUIC 回退不保证成功，未知名称也不能凭 DNS 推断为可解密。参考[MITM 范围](../mitm/hosts.md)。

## 安装了证书，App 仍然连接失败

先在证书页刷新并核对 SHA-256，排除安装的是旧 CA。之后区分客户端和上游握手错误：目标 App 不信任当前 CA，与真实服务器证书校验失败需要不同处理。

Android 7+ 的 App 可能默认不信任用户 CA，或存在 pinning、自有信任库。系统 CA 状态也不能证明所有 App 都信任。`skip_server_cert_verify` 只改变上游校验，不能修复客户端信任。

日志中“握手完成但没有 HTTP 请求”可能来自客户端取消或信任策略，不能单凭这一项确认 pinning。可把域名排除，恢复该目标正常连接，再进一步核对客户端条件。

## 能看到请求，但规则没有生效

| 检查项 | 常见原因 |
| --- | --- |
| 当前配置 | 修改了未选中的配置，或服务应用失败 |
| 扩展开关 | 只开启 MITM，没有开启改写或脚本 |
| 单条开关 | 页面新建规则仍为 `disabled: true` |
| 独立范围 | MITM 命中，但改写/脚本的端口或应用范围不匹配 |
| URL 模式 | 忘记协议、非默认端口、查询参数或 JSON 反斜杠转义 |
| 规则顺序 | 首条宽泛规则覆盖了后面的特例 |
| 处理阶段 | 请求规则写成 response，或反之 |

`/profile$` 不匹配 `/profile?page=1`。响应规则仍按原请求候选 URL 匹配，不应直接假设改写后的目标是唯一匹配依据。

## Header 没有新增，或出现两份

`replace` 只替换已有字段；字段不存在时不会新增。`add` 保留重复字段；想设置唯一值可以顺序使用 `delete` + `add`。请求 Host 有单独限制，见[Header Rewrite](../rewrite/headers.md)。

## 正文不变、截断或显示 Base64

先区分三个限额：请求记录保存了多少、正文规则能处理多少、脚本允许读取/输出多少。预览截断不证明实际流量也被截断。

SSE、gRPC、NDJSON、升级连接、HEAD 和 206 等会跳过正文处理。无效/不支持编码或非 UTF-8 文本也可能保留原文；二进制脚本需正确配置模式。

响应正文默认处理上限为 1 MiB，脚本默认同样为 1 MiB，但由不同字段控制。共享工作预算不足也会跳过正文工作，在服务日志查看具体原因。

## 返回 413 或 502

| 状态 | 重点检查 |
| --- | --- |
| 413 | 需要处理的请求正文是否超过上限 |
| 502 | 上游失败、分帧/正则错误，或非法 `$done` 结果 |

常见脚本错误包括：未设 `requires_body` 就返回顶层 `body`、返回不支持字段、改动 Content-Length/Upgrade、使用错误的头数组格式。`abort: true` 也会以 502 结束。

脚本未捕获异常、超时或源码加载失败通常保留前序处理后的报文并告警；jq 错误通常跳过当前规则。不同失败不能都当作“脚本报错必定 502”。

## 脚本或主动请求没有输出

- 每条完成路径是否调用 `$done`；是否在异步回调返回前提前 `$done()`。
- 是否用了没有实现的 `fetch`、`require` 或其他工具专属 API。
- `allowed_origins` 是否是空数组，重定向目标是否仍被允许。
- `policy` 是否真的是当前配置的 outbound tag。
- `timeout_ms` 是毫秒，客户端 `timeout` 是秒，网络是否被总时限提前取消。
- `console.log` 属于 info 等级，配置或日志页面是否过滤了它。

主动 HTTP 请求不会递归写入请求记录，通过回调与服务日志确认结果。

## Cron 一直没有运行

确认本地服务正在运行、脚本总开关开启、任务未禁用。检查五段/六段表达式、时区和下一次日历触发时间；保存时不会立即执行。

设备休眠错过的任务不补跑，不申请系统唤醒。同一任务已排队或执行时，重复到期也会跳过。可先使用[每分钟日志心跳](../scripts/cron.md#先验证调度)确认路径。

## 远程脚本或 Mock 仍然是旧内容

已有缓存时，下载失败或新脚本编译失败会继续使用旧缓存。查看路由、资源 URL、刷新间隔和日志；首次下载还可能消耗脚本时限。

本地脚本默认缓存到服务结束，需要每次重新加载时使用 `debug: true`。本地 Map Local 每次读取文件。清空请求记录不会清资源缓存。

## 停止记录后为什么还在改写

这是独立开关的预期行为。停用对应配置扩展并成功应用，或停止本地服务，才会结束配置处理。不要用请求页的停止按钮代替关闭改写。

## 反馈问题时提供什么

到 [B-box Issues](https://github.com/giturass/B-box/issues) 反馈应用问题，到[文档 Issues](https://github.com/giturass/B-box-docs/issues) 反馈页面说明问题。

提供安装版本/提交、Android 版本、触发步骤、预期与实际结果、最小配置及相关日志。配置片段与日志可用测试域名复现，提交前去掉真实令牌、Cookie、订阅和个人请求内容。
