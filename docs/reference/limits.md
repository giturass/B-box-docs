# 默认值与限制

以下行为依据[固定源码版本](./sources.md)。当前实现已取消旧版的固定容量与并发配额，用户显式设置的正文限制和执行期限继续生效。KiB / MiB 分别是 1024 / 1048576 字节。

## 开关与范围

| 项目 | 默认 | 行为 |
| --- | --- | --- |
| MITM / HTTP 改写 / 脚本 `enabled` | false | 三个独立开关 |
| MITM `hosts` | 空 | 空列表不解密；不设条数配额 |
| MITM `ports` / `packages` | 空 | 空时不附加对应限制 |
| MITM `tcp` | false | 按需开启非 HTTP TLS 解密 |
| MITM `h2` | true | 显式 false 仍有效；只接受 h2 的连接在关闭时透传 |
| MITM `skip_server_cert_verify` | false | 默认验证真实上游 |
| MITM `block_quic` | true | 只作用于可观察名称且命中范围的 QUIC |
| 改写 / HTTP 脚本 / 记录端口 | 80、443、8080、8443 | 各自配置，按原始目标端口；不设条数配额 |
| 应用筛选 | 空列表 | 不限应用；指定后未知归属不能匹配 |

## 正文限制如何设置

| 位置与字段 | 缺省或 `0` | 正整数 | `-1` |
| --- | --- | --- | --- |
| `http_rewrite.max_body_bytes` | 不限制 | 请求与响应共用的字节上限 | 不限制 |
| `http_rewrite.max_request_body_bytes` / `max_response_body_bytes` | 继承共同值 | 覆盖相应方向的上限 | 该方向不限制 |
| `scripts.max_body_bytes` | 不限制 | 拦截正文及脚本输出的字节上限 | 不限制 |
| HTTP 规则的 `max_body_bytes` | 继承 `scripts.max_body_bytes` | 覆盖当前规则 | 当前规则不限制 |
| 单条规则的 `http_client.max_body_bytes` | 不限制 | 主动 HTTP 输入/输出上限 | 不限制 |
| 记录设置的 `bodyLimit` | 每方向保存 64 KiB | 每方向保存的字节上限 | 保存完整正文 |

数值须在字段整数可表示范围内，小于 `-1` 会被拒绝。主动 HTTP 限额与拦截正文独立；记录限额仅改变保存量，不截断实际流量。

例如将下面的[正文限制片段](/examples/body-limits.json)合并到已有 `experimental`，可以把改写请求限制为 8 MiB、响应及拦截脚本限制为 2 MiB。这些数值是示例选择，不是默认值；仍需另行添加和启用相应规则。

## 执行与联网

| 项目 | 默认或行为 |
| --- | --- |
| HTTP / Cron `timeout_ms` | 缺省或 `0` 为 5000 ms；正整数为毫秒期限，`-1` 不增加期限 |
| 主动 HTTP `timeout` | 默认 5 秒；正数为秒数，`-1` 不增加期限，`0` 无效 |
| URL 资源刷新间隔 | 默认 86400 秒；接受可表示为 duration 的正整数秒 |
| URL 资源下载 | 不另加固定总时限；服从调用方及服务取消 |
| 主动 HTTP 累计调用 | 默认不限；`max_requests` 正整数可限制，失败与被拒绝调用也计数 |
| `allowed_origins` | 省略/null 不限制，空数组禁止；精确 origin 列表不设条数配额 |
| 主动 HTTP / URL 资源重定向 | 检查重定向循环，不设固定跳数配额 |
| HTTP / Cron 解释器、主动 HTTP 并发 | 不设固定数量配额；每次脚本使用独立 VM |
| Cron 重复到期 | 不同任务独立启动，同一任务运行期间跳过重复到期 |
| 定时器 delay | 非负有限毫秒数，须可表示为 duration；实际最小调度间隔 1 ms |
| 待执行定时器、日志 | 不设每次执行的数量或日志截断配额 |

脚本的资源加载、网络、定时器与执行共享总期限；`-1` 不会解除上层请求取消、`$done` 或服务停止。每条完成路径仍须调用 `$done`。

## 正则、jq 与编码

正则表达式、捕获组、替换次数、回溯栈，以及 jq 表达式、输出数量和嵌套不设 B-box 固定配额。回溯与 jq 使用当前请求的取消信号，JS 正则使用当前 VM 的中断；输出仍遵守用户正文限额。

Content-Encoding 支持 identity、gzip/x-gzip、deflate、br、zstd，不再固定为最多三层。zstd 保留协议要求的 8 MiB 最大窗口；窗口大小不等于整段正文大小。

## 记录、缓存与存储

| 项目 | 当前行为 |
| --- | --- |
| 配置 JSON、规则、资源、主机列表 | 不设固定容量或数量配额，仍做格式校验 |
| Map Local 文件、JavaScript 源码 | 不设固定文件大小上限 |
| 请求记录、头部、trailers、磁盘总量 | 不设固定配额；记录保留到明确清空 |
| 正文详情页 | 每页 16 KiB，按需翻页，UTF-8 字符保持完整 |
| 页内 JSON 格式化 | 派生显示文本最多 64 KiB，超出时显示原文；不限制保存或导出 |
| HAR / cURL | 流式读取已保存内容，不再使用 64 KiB 解码截断 |
| URL 资源缓存 | 不设累计磁盘配额；配置激活时回收不再引用的资源 |
| 持久存储 | 不设键/值长度、键/命名空间数量、容量及单次读写次数配额 |

不设固定配额不代表设备资源无限。正文缓冲按实际长度记账，生产环境的 `bodyBudgetLimit=0` 表示没有全局容量配额；该统计不等于进程内存用量。按实际请求规模设置正文限制，并通过[记录与导出](../mitm/capture.md)区分分页、截断和未完成。
